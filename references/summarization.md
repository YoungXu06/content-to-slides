# 5-Question Summarization Framework

在生成最终文件之前，用五个问题建立内容主线与证据边界。答案用于共同的逐页规划，不用于生成后的评审或重写。

## 五问骨架

| 问题 | 要确定的内容 |
|------|--------------|
| 一句话核心 | 原文支持的最重要结论是什么？用一句完整的话概括，不限死 25 字，不丢条件。 |
| 听众入口 | 从哪个具体场景或问题开始，听众最容易理解？不制造焦虑或反常识标签。 |
| 关键支撑 | 哪三至五个论点、过程或例子解释核心？每个有来源依据，不能只是话题名。 |
| 重要限定 | 结论在哪些条件下成立？有什么未验证之处或容易混淆的概念？ |
| 判断落点 | 听完能明确理解什么？如材料支持，可以说明应用方式，不要求观众采取行动。 |

没有足够依据时继续获取材料或明确说明不足，不为了满足页数编造。

## 证据边界

- 对每个数字、比较和技术机制，明确出处及所比较的对象。
- 分清来源中的实测结果、作者主张、假设场景和解读。不把假设改成已发生的事实。
- 同一测试结果不自动推广到其他任务；不同指标不拼成一个夸大的总体结论。
- 原文没说原因时，不用“所以”添出因果。并列事实可以通过分类或共同问题组织。
- 为普通听众解释术语时，可以展开原意；不能额外补造数据、故事或性能承诺。

## 从内容到逐页规划

默认按听众理解顺序选择：场景 → 必要概念 → 机制 → 证据或例子 → 限定与结论。定义、比较、结果和限定可分可合，不强制九页结构，不强制单设“关键判断”或“行动”页。

每页回答一个具体问题，同时安排屏幕文字和口播要解释的内容。页面可以是简短标签，讲稿必须是完整解释，不能照着标签连读。

生成前确认前页已经提供后页所需的概念即可。不要求“抽掉任一页主线就崩掉”：例子、对照、背景也有价值。不为了强连贯把独立论点写成虚假的因果关系，不在每页末尾造悬念。

详细语言和承接方式见 [voice.md](voice.md)。完整的前置规划与单次输出协议见 `SKILL.md`。

## 生成前的取舍

| 常见偏差 | 规划时采用的方式 |
|----------|------------------|
| 把摘要当核心 | 用一个有条件、有对象的明确结论，替代“本文探讨了……” |
| 页面只有话题名 | 明确这一页回答的问题和支撑事实 |
| 每页重新介绍背景 | 背景只安排一次，后页使用已解释的术语 |
| 为压字数省略逻辑 | 减少次要分支，保留主语、条件、因果和术语说明 |
| 收束变成训导 | 说明已有结论和适用范围，不用“别再”“必须”劝导 |
| 材料太少 | 在生成前指出缺失，索要补充材料，不用新故事撑页数 |

## 示例：远程协作

以下是虚构素材的规划演示，不是关于远程工作的事实来源。假定材料明确描述某团队远程后会议增加，并分析同步协调、书面记录与临时沟通的变化。

五问答案：

- 核心：这个团队的远程协作效率受原有协调流程的影响。
- 入口：远程之后会议更多，任务仍需反复确认，原因是什么？
- 支撑：临时沟通减少；信息仍靠同步会议传递；决策缺少可检索记录。
- 限定：这是一个团队的经验，不能直接推广到所有远程工作。
- 落点：区分需要即时讨论的问题与适合书面记录的信息。

一种六页安排：

1. 远程之后，协调时间花在哪里？
2. 原先的临时沟通承担了什么作用？
3. 临时沟通减少后，会议如何接替它？
4. 哪些信息可以通过书面记录传递？
5. 即时讨论与书面记录的适用范围。
6. 回到协作效率：流程、记录和适用条件。

这份规划同时指导画面和讲稿。口播从具体经历说明机制，不把上述标题直接念成六句结论，也不另加生成后的大纲检查阶段。
