# Speaker Script Voice Guide

目标：让一个熟悉内容的人，把事情讲给聪明但非本专业的听众听。讲稿会直接送入 TTS，必须客观、自然、简洁，而且只听声音也能理解。

**简洁指减少重复和枝节，不指把句子压成摘要。完整意思、自然语气、必要的连接，优先于少几个字。**

## 生成前的写作约定

在生成最终文件前，用这些约定决定逐页内容；不要把它们变成生成后的评分表。

1. 写成一段能连续听懂的解释，不写成几条 bullet 去掉标记后的拼接。
2. 明确谁在做什么，保留原因、条件和转折；省略主语时，所指对象必须唯一。
3. 新术语先用日常语言说明含义，再使用简称。不能为了短而跳过解释。
4. 用自然的长短句和必要的连接词，不限定单句字数，不逐个计算代词次数。
5. 页序遵循听众的理解顺序。承接可以自然延续，也可以简短回扣；不要求每页首尾使用固定句式。
6. 所有事实、例子、比喻及结论都受来源和适用条件约束，不能为了流畅编造补充材料。
7. 正文直接写成适合 TTS 的纯文本；不安排生成后的润色、禁词扫描或格式修补阶段。

## 一、先让人听懂，再考虑压缩

### 1.1 保留理解所需的连接

句子里可以自然出现“如果”“因为”“但”“所以”“比如”“也就是说”。这些词承担条件、因果、转折或解释时就是内容，不是水词。不要用更短的句号拼接替代它们，也不要套用同一组连接词写每一段。

一个常用的理解顺序是：具体场景 → 发生了什么 → 为什么难以判断 → 方法要解决什么 → 限制在哪里。按内容需要取舍，不强制每页包含全部环节。

### 1.2 用户提供的反例

不采用的表达：

“调用一个模型，回复可能来自另一组权重。路由服务为省钱换成便宜模型，输出质量看不出来。FlashProve要查的就是这件事，难在权重本身保密。”

问题不在于禁词，而在于四个意思被挤成四个结论。“另一组权重”还没有解释，第二句省掉了假设条件，“这件事”指代模糊，最后一句把新的困难直接塞进结尾。听众需要自己补出逻辑。

在只使用这段已给信息的前提下，采用这样的表达：

“你通过接口调用一个模型，通常会以为，回答就是这个模型生成的。但如果服务为了节省成本，换用了一个更便宜的模型，单看回答的质量，你未必能分辨出来。FlashProve关注的就是这个问题：怎样确认实际运行的是指定模型的那组权重？麻烦在于，这些权重通常需要保密，不能直接公开出来让用户检查。”

这个示例只演示表达方式，不作为 FlashProve 的技术介绍或额外事实来源。正式生成时，以输入材料为准。

保留了必要的连接和解释，文字略长，但听众不需要倒回去猜上一句是什么意思。不要把“更自然”理解成加感叹词、网络梗或虚构故事。

### 1.3 避免电报式压缩

- 不把“为了节省成本，服务可能换用便宜模型”压成“路由省钱换模型”。
- 不把“单凭回答质量，用户未必能识别这种替换”压成“输出质量看不出来”。
- 不把两件不同的事塞进“难在……”一句里，先解释困难和前文的关系。
- 不连续用“一句结论。另一句结论。再一句结论。”代替解释。
- 先少讲一个次要要点，再考虑减少表达长度；不能通过删掉条件和因果凑字数。

## 二、亲和性来自共同理解

### 2.1 允许自然的“你”“我们”

描述使用场景时可以说“你通过接口调用模型时”；解释共同的理解过程时可以说“我们可以把权重理解成……”。不设全篇次数配额。

避免的是“你必须明白”“聪明的人都应该”“我们一定要认识到”等训导和强行站队，不是代词本身。也不要为了回避代词，把每句话都写成“开发者”“用户”“研究者”的客观通报。

### 2.2 日常动词，完整语气

优先用“调用、换用、检查、比较、保留、公开”等能指向实际动作的词。可以自然使用“了、就、还、也”，不必把它们当冗余删除。不要为了口语感刻意加“呀、呢、啊”，也不假装有个人经历。

亲和性来自照顾听众的理解速度：先讲熟悉的场景，再带出新概念。熟悉的术语可以直接用，陌生术语不要一口气堆三个。

## 三、客观与表达边界

- 把可能性说成可能性。使用“如果服务换用了模型”，不能无依据断言某个服务已经这样做。
- 把评测结果的任务、指标、对照组保留下来。局部结果不能扩写成普遍规律。
- 来源只表明相关性时，不补写因果；无法确定原因时说明未知，不用“合理解释”包装猜测。
- 判断可以明确，但依据和适用范围要清楚。不在每个句子前机械添加“从公开数据看”。
- 同义改写和通俗解释不能引入来源没有的数据、动机、时间或性能承诺。
- 教程场景可以给具体操作，普通解读不要求听众改变立场或采取行动。

## 四、减少模板腔

### 4.1 默认不主动使用的修辞

“反直觉的是”“更狠的是”“更绝的是”“颠覆认知”“炸裂”“封神”“99%的人不知道”，不用于标题、口播或社媒帖文的包装。

#### 否定—重定义句式：默认不用

“不是A，而是B”“不只是A，而是B”“真正的X是Y”“表面上A，实际上B”“与其说A，不如说B”，
以及把它们拆开仍保留否定骨架的写法（“靠的是X，而不是Y”“关键在于X，不在于Y”），
属于同一族修辞。它们把「先否定一个说法、再给出更高级的说法」当作解释，读起来像在
下判断，实际没有讲清机制。**默认一次都不写**，包括口播、页面标题和社媒帖文。

这类句式在过去的输出里几乎是每页一次（单篇讲稿出现过 7 次“不是…而是”、
“真正的X是Y”共 15 次），所以按以下方式处理：

1. **有信息要传达时，直接讲事实。** 不先立一个靶子再推翻。
   不写“顶级销售不是话术，而是信任”；
   改写“他谈合作时先问对方真正要什么，再谈条件，所以对方愿意继续”。
2. **确实需要辨析两个概念时，写明两者的具体差别。**
   不写“这不是A，而是B”；
   改写“A 关注 X，B 关注 Y；在这个场景下 B 更适用，因为 Z”。
3. **想强调某个判断时，给它依据和范围。**
   不写“真正的领导力是让人想去做”；
   改写“他带团队时不发指令，只说明目标，成员自己决定怎么做”。

整篇最多允许 1 次，且必须同时满足：来源本身就在对比两个概念，且改写后会丢失信息。
其余情况一律换成正面陈述。用户明确点名要用这类句式时从其要求；原文引述或专门讨论
这些表达时须明确语境。

**也不要用同类结构连续收尾。** 常见的坏节奏是每页最后一句都写成
“真正的价值不是 X，而是 Y”。规划页序时就把这一点定下来：相邻两页不要在同一位置
用相同的收法，第二页改成先给事实再收束。

真实反例（同一篇讲稿相邻三页各一次）：

- “核心不是更大的 prompt，而是更强的交接和验证纪律。”
- “真正改变的不是一个 Agent 能写多少代码，而是让……解耦。”
- “真正的价值不是几个 Agent 在聊天室里互相聊天，而是一个……生产系统。”

改写时不要只换同义词，而要直接讲这页的事实：写清系统做了什么、耗时花在哪、
换来了什么结果。判断句可以保留，但依据要具体。

上面的反例可以这样改（事实与数字均未改动）：

- “跑得这么久，靠的是交接和验证上的纪律；把 prompt 写得更大，解决不了方向漂移。”
- “它把「人类定义要什么」和「系统自主执行多天」两件事拆开：执行、验证、交接、
  自愈都交给系统，人类负责定义方向、做关键判断。”
- “几个 Agent 在聊天室里互相聊天，和一套可运行、可验证、可恢复的生产系统，
  区别就在这里。”

改写后否定结构消失，信息量不变，句子也不再像在下判语。

#### 其它节奏套路

不连续用“问题的关键在于”“更值得注意的是”“这背后是”承接段落；不把每页结论都收成
一句判断句。句子之间用具体信息推进，而不是靠评价性短语起承。

### 4.2 不用更短的模板替换旧模板

不要把“这意味着”统一换成“结果是”，也不要把“也就是说”统一删除。要按句子的关系选择表达。

“闭环”“对齐”“权重”等如果是讨论对象，可以使用并解释；如果只是修辞装饰，换成具体动作。事实性描述中的“部分”“一些”“可能”可以保留，它们可能是必要的范围限定。

### 4.3 不强制造金句和悬念

不用“问题来了”开启每一页，不用“这引出一个更难的问题”结束每一页。不要求截图金句，不安排自媒体式高潮或“下一页揭晓”。

不念舞台指引：“这一页我将”“接下来请看”“请大家看这里”。不加套话式问候、感谢或卖关注，除非用户明确需要。

## 五、页间自然承接

**讲稿是一段完整讲解，分页只是与画面对应的结构。** 在生成前，为每页确定它回答什么、承接哪个已解释的概念、留给下一页什么信息。

- 前页结论已完整时，可以正常收尾；下一页通过原因、例子、比较、步骤或适用条件接续。
- 必要时复现具体名词，但不用每页都重复上一页的末句。指代唯一时，使用“这种替换”“这个限制”很自然。
- 进入新章节时，用一句话交代为何需要切换视角。不反复介绍全篇背景。
- 有设问就尽快回答；只有下一页确实解释该问题时才保留承接设问，不制造空悬念。
- 结尾回到核心问题和已说明的限制，不引入新术语，不替听众升华立场。

表达示例（假设素材已说明这些信息）：

前页收尾：“单看回答质量，用户未必能确认实际用的是哪个模型。”

后页开头：“要确认模型身份，就需要把检查对象进一步缩小到模型权重。但这些权重通常需要保密，验证方法还得考虑怎样保护它们。”

承接在内容里，不依赖“前面说过”“下一页会讲”。并列论点可以按明确分类展开，不必编造不存在的因果。

## 六、TTS 文本约定

- `script.md` 的每个 `## Slide N · 标题` 下只写口播纯文本段落。H1、H2、顶部总时长行和分隔线是文档结构，不送入 TTS。
- 不在口播正文写 Markdown 修饰、列表、网址、HTML/SSML、舞台提示或装饰符号。来源链接放在页面出处区域，不把完整网址念出来。
- 用逗号、句号和自然设问表达停顿；不靠碎句、单字独占一行、密集破折号或空行模拟重音。
- 括号里的必要内容改为一句正常说明。不用斜杠、箭头、加号压缩成关系式；公式说出含义，不逐个念 LaTeX 符号。
- 中文与英文、数字之间默认不另加排版空格；英文词组内部保留空格。排版规则不用于切断句子。
- slides 保留官方名称和数字；讲稿采用可读形式，如“GPT 5.4”“百分之十二”“一千五百万参数”。保留数值、单位和版本身份，不做失真的笼统改写。
- 数字、英文和标点的读法依具体 TTS 引擎而异；不声称某种格式一定漏读或某种写法必然更稳。生成前统一容易混淆的读法，不在生成后加扫描修改环节。

## 七、篇幅与节奏

普通页以约 100–180 字为参考，开场和收束可短一些，解释关键机制可以略长。**这是规划预算，不是每页的合格阈值**，不为了达标统计、补字或压字。

不限定句子必须 15–35 字。短句交代结论，中等长度句子连接条件和原因；长句包含多个独立意思时，在自然语义边界展开。删掉 H2 标题也应能连续听懂，但不安排写完后再通读修改。

篇幅紧张时，先减少次要分支和重复例子。术语解释、必要主语、因果连接和范围限定属于必要信息，不能先删。

可按中文口播每分钟约 220–260 字粗估总时长；实际时长依语速、英文及停顿变化，标注“预估”，不声称等于最终音频时长。

## 八、单次生成与社媒帖文

生成流程以 `SKILL.md` 的单次输出协议为准。本文件只指导生成前的内容取舍和生成时的语言，不增加独立审稿、禁词扫描、润色、重写或试配音循环。

社媒帖文仍放在 `script.md` 末尾：50–100 字为参考，一段正文，另起一行 3–5 个标签。用来源中的具体信息说明视频讲什么，不复制开场全文，不加“点赞收藏”“三连”等引导。与讲稿一起生成，不额外建立审稿阶段；帖文、标签和文档结构不作为逐页配音。
